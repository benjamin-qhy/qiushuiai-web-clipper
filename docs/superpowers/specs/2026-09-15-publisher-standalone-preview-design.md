# 内容发布工作台独立预览页设计

## 目标

为 `@qiushui/content-publishing-workbench` 提供一个可单独启动的开发页面，使工作台无需安装浏览器插件即可在普通浏览器或 Codex 内置浏览器中查看和调试。独立页面通过后，仍需在 Chrome 插件环境验证真实的网页提取、草稿路由、浏览器存储和侧边栏打开链路。

## 范围

- 新增独立 Vite 预览页和根目录启动命令。
- 使用真实的 `ContentPublishingWorkbench` 组件与正式样式。
- 注入覆盖标题、段落、列表、引用、代码、表格、重点标记和显式分页符的示例草稿。
- 提供仅用于预览的模型、提示词、确定性 AI 生成、草稿保存、布局保存和文件下载适配器。
- 在内置浏览器完成页面加载、主要交互和控制台错误检查。
- 保留现有插件入口及其生产行为不变。

不在范围内：连接真实 AI 凭据、复用 `browser.storage.local`、模拟网页提取、替代最终插件集成测试。

## 方案

在 `packages/content-publishing-workbench/playground/` 建立独立 Vite 页面。页面直接引用工作台包源码，因此修改组件和样式后可热更新。预览宿主集中提供示例 `PublisherDraft` 和 `WorkbenchAdapters`，不在工作台生产代码中加入 `preview` 分支。

相较于在插件入口增加 `?preview=1`，独立页面不会把模拟数据和适配逻辑打入插件入口，也能形成清晰的开发命令。相较于空草稿自动回退，它不会掩盖真实插件的草稿丢失错误。

## 数据与交互

1. 页面启动时构造固定的示例草稿。
2. 工作台通过模拟适配器读取两个示例模型和两个提示词。
3. 模拟生成返回固定 Markdown，便于重复检查覆盖确认、分页和卡片预览。
4. 草稿与布局写入预览页自己的 `localStorage` 命名空间，刷新后可验证恢复，不接触插件数据。
5. 下载适配器使用浏览器 Blob 下载能力，验证工作台生成的 PNG/ZIP 文件。
6. “打开设置”在页面内给出预览环境说明，不跳转插件设置页。

## 错误边界

- `localStorage` 数据无效时回退到示例草稿或默认布局。
- 模拟生成不发起网络请求，也不读取任何密钥。
- 预览页故障不得改变插件入口的空草稿提示或适配器行为。

## 验证

- 先写测试证明预览宿主能提供示例草稿、模拟模型和确定性生成结果，并观察测试因模块缺失而失败。
- 实现后运行预览相关测试及完整 Vitest。
- 运行 `pnpm compile`、`pnpm build`、`git diff --check` 和文档一致性检查。
- 启动独立页面，在 Codex 内置浏览器验证三栏、编辑、生成、主题、封面、分页和控制台。
- 最后运行 Chrome 插件，验证普通网页提取后能打开真实右侧工作台。

## 文档同步

新增启动命令和预览入口后，同步更新 `CLAUDE.md` 的常用命令与入口文件章节，并完整同步到 `AGENTS.md`。
