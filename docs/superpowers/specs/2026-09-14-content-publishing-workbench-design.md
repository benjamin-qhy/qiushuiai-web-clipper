# 内容发布工作台设计

## 目标

在 popup 成功提取文章后增加“内容发布工作台”按钮。点击后在 Chrome 右侧打开工作台，将完整 Markdown 原文加工为可编辑创作稿，再排版为可本地保存的小红书 3:4 文字卡片。

第一版不登录或调用小红书发布接口，不把成品发送到任何第三方平台。Firefox 复用同一 React 工作台，但以独立扩展页面承载。

## 视觉目标

采用 Product Design 探索中选定的第一套“克制编辑台”：

- 白色基础表面、近黑文字、暖灰辅助面；`#f97316` 仅用于关键操作与选中态。
- 细分隔线、低圆角、极少阴影，以信息层级和留白区分区域。
- 默认三栏比例为 `30% / 35% / 35%`，右栏突出 3:4 成品卡片。
- 六种卡片样式参考用户提供的小红书截图的信息层级、页码、重点笔触和样式选择方式，但不逐像素复制。

## 工作台入口与宿主

- popup 仅在提取成功后显示“内容发布工作台”按钮。
- 点击按钮生成工作台草稿标识，同时启动本地保存并在同一用户手势中打开当前标签页的 Chrome side panel；侧边栏通过当前标签页映射等待草稿就绪，避免异步存储使用户手势失效。
- 抖音收藏页仍使用现有 `douyin-sidepanel.html`；其他页面的 side panel 指向新的工作台入口。
- Firefox 或不存在 `browser.sidePanel` 时，在新标签页打开相同工作台入口。
- 工作台作为隔离的 React + shadcn 功能包存在；Vue popup、设置页和抖音侧边栏不迁移。

## 原文快照

- 飞书和金山文档使用 `blocksToMarkdown()` 得到完整 Markdown；通用网页直接使用 `DocContent.markdown`。
- 标题、来源 URL、作者、发布时间、创建时间和标签作为独立元数据保存，不生成 YAML frontmatter。
- 左栏只读渲染完整 Markdown；原文图片可以显示，但不进入第一版卡片成品。
- 原文快照在当前工作台草稿内不可修改。

## 三栏布局

### 原文快照

只读 Markdown 预览，显示文章元数据和正文。

### 创作稿

- 初始为空。
- 提供模型、推理级别和创作指令选择。
- 创作指令可以选择任一现有系统提示词，也可以切换到手工输入；不增加提示词类型字段。
- 提供“编辑 / 预览”切换。编辑态直接编辑 Markdown，预览态渲染 Markdown。
- 已有创作稿时重新生成必须确认覆盖；不做版本历史和流式输出。

### 卡片成品

- 从创作稿实时生成分页预览。
- 可浏览当前页、页码和缩略图。
- 封面卡可开启，默认关闭；关闭时正文第一页就是第一张图片。
- 页数由排版结果决定，不设上限，不截断内容。
- 可保存当前页 PNG，或将全部 PNG 打包为 ZIP。

### 响应式行为

- 宽屏显示三栏；中等宽度显示两栏；窄侧栏显示“原文 / 创作 / 成品”标签页。
- 每栏可隐藏和恢复；至少保留一栏可见。
- 拖动栏宽、显隐状态和最近布局全局保存，并提供“重置布局”。

## AI 生成

- 模型选择器列出设置中已配置且可用的全部模型。
- 推理选择器根据模型能力展示合法级别。
- 默认使用上次成功生成时的模型和推理级别；换到不支持已保存推理级别的模型时回退为关闭。
- 成功生成后更新全局最近模型与推理级别。
- 手工创作指令只保存在当前工作台草稿中，不加入系统提示词列表。
- 没有模型，或模板模式未选择模板时，禁用生成并提供设置入口。
- 模型请求将用户创作指令与固定输出格式契约分开维护、调用时组合。

固定输出格式契约要求模型返回 Markdown，使用短段落、标题、列表、`**粗体**` 和 `==重点标记==`。模型决定语义重点，排版器不猜测关键词。

## Markdown 与分页

- 支持标题、段落、粗体、斜体、重点标记、列表、引用、链接、行内代码、代码块、表格、分隔线和显式分页。
- `<!-- pagebreak -->` 是唯一手动分页标记；`---` 保持 Markdown 分隔线语义。
- Markdown 先解析为语义块，再在隐藏测量区按最终卡片尺寸、字体和 CSS 测量。
- 自动分页优先在块边界发生；标题与其后的实质内容保持在同页，避免页尾孤立标题。
- 单块超过整页时才按可测量的文本片段继续拆分，并保留行内语义。
- 预览和导出共用同一个页面计划和卡片 DOM。
- 字体加载和图片解码完成后才允许导出。

## 卡片样式

首批固定六种原创样式，共享内容和页数，只改变视觉：

1. **基础**：石墨灰底、白字、荧光绿重点笔触。
2. **科技**：深海军蓝底、青色微网格、电蓝细节。
3. **简约**：暖白纸张、编辑式排版、黄色重点笔触。
4. **边框**：白底、醒目的天蓝结构边框。
5. **手帐**：象牙色横线纸、克制的植物墨迹。
6. **柔和**：薄荷绿与蜜桃色柔和纸张、蓝色引号。

选择卡片样式不能改变 Markdown、分页结果或页数。第一版不提供字号、颜色、边距等自由设计参数。

## 导出

- 固定输出 `1242 × 1656` PNG，严格 3:4。
- 当前页命名为 `{安全标题}-{两位页码}.png`。
- 全部保存生成 `{安全标题}.zip`，内部包含顺序 PNG。
- 超过 20 页时显示性能提示，但允许继续。
- 仅虚拟化显示当前页附近预览；批量导出逐页执行，避免同时持有大量画布或 Blob。
- PNG 导出前检查字体、垂直溢出和文件类型；预览与导出必须视觉一致。

## 草稿

- 工作台草稿以来源 URL 和提取时间标识，保存在浏览器本地存储。
- 当前标签页只保存一个指向活动工作台草稿的映射，侧边栏据此加载刚创建的草稿。
- 保存原文快照、创作稿、创作指令模式与手工内容、模型、推理、卡片样式、封面开关、当前页和布局状态。
- 再次打开同一草稿时恢复状态；提供“重新开始”，仅清空创作相关状态，不删除原文快照。

## 组件边界

React 功能包通过适配器接收：

- 原文快照读取与草稿保存；
- AI 模型目录、系统提示词目录和补全调用；
- 全局最近选择读写；
- PNG 与 ZIP 本地下载；
- 打开设置页。

功能包不直接依赖 WXT、Vue、Chrome API、具体 AI SDK 或 Obsidian 文件系统。宿主扩展负责实现适配器。

## 验收标准

- popup 提取完成后能打开正确工作台，且不破坏抖音侧边栏。
- React 工作台可独立挂载，并能在 Chrome side panel 与 Firefox 扩展页运行。
- 三栏拖动、隐藏、恢复、响应式切换和布局持久化可验证。
- 模型、推理、模板/手工创作指令及覆盖确认行为可验证。
- Markdown 解析、重点标记、显式分页、真实高度分页和标题保护有单元测试。
- 六种样式均可预览，切换样式不改变页面计划。
- 当前页 PNG 与全量 ZIP 尺寸、顺序、文件头和命名正确。
- 超长文章不会被截断，并采用虚拟预览与顺序导出。
- `vitest run`、`pnpm compile`、Chrome 与 Firefox 构建通过；修改源文件后最终必须运行 `pnpm build`。
