# 多平台模型配置设计

## 目标

设置页左侧新增独立可见的“模型配置”。用户可以配置任意数量且平台不重复的模型平台；实际调用时从已配置平台及其 Pi 模型目录中选择模型。最后一次成功测试的模型成为下一次默认模型。

## 配置与迁移

- `Settings.aiPlatforms` 保存平台实例：稳定 ID、Pi provider ID、API Key，以及自定义 OpenAI 兼容平台所需的 Base URL 和模型名。
- `Settings.lastUsedAIModel` 保存平台实例 ID 与模型 ID，不保存推理程度。
- 已有 `aiConfig` 在读取时迁移为一个“OpenAI 兼容”平台，确保原有 DashScope 地址、密钥和 `qwen-long` 不丢失。
- 平台数量不设上限；同一 Pi provider 只允许配置一次。

## Pi 接入

- 使用 `@earendil-works/pi-ai`，不使用已弃用的 `@mariozechner/pi-ai`。
- 通过 Pi 内置 Provider 集合提供平台与模型目录，并过滤浏览器不支持的 Bedrock 和 OAuth-only 平台。
- 内置平台的实际请求由 Pi 统一完成；自定义 OpenAI 兼容平台继续复用现有请求实现。
- 推理程度默认关闭；开启后按模型能力提供最低、低、中、高、很高、最高等可用级别；测试发送成功后更新最后使用模型。

## 界面

- 左侧导航在“同步”之后显示“模型配置”。
- 配置区允许新增、修改、删除平台，并录入 API Key。
- 配置区下方是测试区：一个按平台分组的模型下拉框、推理程度、测试指令、发送按钮和结果。
- 模型下拉框以平台名称为不可选择的分组标题，组内列出该平台的模型；一个选项同时对应平台 ID 与模型 ID。最后使用模型仍有效时默认选中它，否则选中首个可用模型。

## 调用与错误处理

- 未配置平台、密钥为空、模型失效时给出明确提示。
- 只有请求成功才持久化最后使用模型；失败不改变默认值。
- 删除最后使用的平台后清空失效选择，并在下次使用时回退到首个有效平台与模型。

## 验证

- 存储测试覆盖旧配置迁移、无限平台保存和失效选择回退。
- AI 层测试覆盖目录过滤、模型解析、推理参数和成功后更新选择。
- UI 回归测试覆盖独立导航、测试指令输入和推理程度默认关闭。
- 运行全量 Vitest、`pnpm compile` 与 `pnpm build`。
