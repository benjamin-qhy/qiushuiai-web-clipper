# 海奇AI发布

一次 Skill 调用负责整理参数、上传素材、提交任务、跟踪结果，并在授权范围内接续。所有平台上传、填写和点击均由 **API → 浏览器扩展 → MultiPost 平台适配器**执行。浏览器工具仅用于只读核对，不能代替扩展完成操作。

本技能随海奇AI剪藏仓库交付，不自动安装到全局。命令在仓库根目录运行，使用 Node 24 和项目依赖。先读 [参数与调用](references/requests.md)；涉及恢复、重复调用或结果不明时读 [接续与结果](references/recovery.md)。接口以仓库 [API说明](../../packages/publishing-api/README.md) 及当前服务返回为准。

## 输入与确认

接受自然语言、素材目录或结构化参数。整理以下输入：

- 内容形式：`dynamic`（文字/贴图图文）、`video`、`article`。
- 每个目标的平台、账号、电脑；浏览器和用户配置可省略，使用 API 默认值。
- 最终文案、素材顺序、横竖封面、精确合集名称及是否原创。
- 结束动作：`stay`（填好保持）、`save_draft`（保存草稿）、`publish`（发布）。未指定时按 `stay`，不推断公开发布授权。
- 执行方式：`single` 或 `continuous`，默认 `continuous`。这是 Skill 本地控制参数，**不发进 API 请求体**。

`single` 创建一次任务并查询结果，遇到暂停即报告。`continuous` 同样只创建一次任务，允许查询、只读核对及白名单原页接续；不是重复创建发布任务。素材上传、发现和查询本身也需要接口调用，因此“一次提交”不等于全程只有一次 HTTP 请求。用户一次指令可以让 Skill 完成多次必要调用。

向用户简要列出最终内容、目标和结束动作；已有对应授权时直接继续，不重复确认。原创声明、接受平台裁切、公开发布分别沿用**本篇、指定账号**的明确授权。缺失必需选择时只问缺项；不能以“为了成功”改变内容、账号、封面或结束动作。没有草稿功能时，只有用户已明确授权该目标可直接发布，才能选择 `publish`。

## 执行

1. 指定 `HAIQIAI_API_URL` 和 **显式设置** `HAIQIAI_API_KEY_FILE` 为 Skill 专用密钥文件；缺少 Skill 凭据就停止，避免客户端默认使用管理密钥。密钥不进入聊天、任务正文或仓库。远程 API 使用 HTTPS，并确认执行电脑可访问。
2. 查询 executors、accounts、capabilities，核对内容类型及最终动作是否开放。平台名称映射到服务真实平台标识，不猜账号 ID；浏览器/配置留空交给 API 默认解析，入队后不得换安装。账号登记不代表登录，扩展必须在填写前核对真实账号。未适配的平台或动作单独报告，不能把有上游脚本当成已开放能力。
3. 在 `.haiqiai-publishing/skill-runs/<唯一运行目录>/` 保存确认范围、输入、素材回执及调用记录。先检查是否有本次已有任务/回执；继续已有任务时读取它，不新建。同一运行记录每个 taskId、目标、结束动作、调用次数和最后状态，恢复会话仍保留预算。
4. 按参数引用上传素材，确认 ready 后构造原生 API 请求。按**内容类型、执行模式和结束动作**分组；同组可有多个平台/账号目标。不同 finish 不能塞入同一个共享 confirmation 的请求。内容保持用户确认版本，合集全等匹配，不截断或自动删标签。
5. 用现有客户端向 `/v1/tasks/dynamic`、`/v1/tasks/video` 或 `/v1/tasks/article` 提交。每个分组保存独立请求和幂等回执；取回 taskId 后只查询该任务。超时复用原请求及原回执路径，不能换幂等键重发。
6. 每约 15 秒查询一次任务及需要的 attempt；每次等待不超过 60 秒。逐目标处理：成功目标结束；仍排队/执行的继续等待；`continuous` 遇到可接续情况按参考文档处理，其他情况保留现场并报告。一个目标受阻不妨碍其他已授权目标完成。
7. 本次主动跟踪默认最多 20 分钟，每目标最多 12 次接续、2 次只读结果核对；同一原因和实际进度连续两次未变即停止接续。新 attemptId/时间变化不算进展。达到预算时说明任务可能仍在运行，保留 taskId，不能标成失败、自动取消或重建任务。用户明确要求继续时可开新跟踪窗口并保留历史。

## 交付结果

逐目标报告平台/账号、结束动作、实际状态、证据链接或草稿所在浏览器、taskId，以及尚未完成的原因和下一步。多平台部分成功就明确列出部分成功，不用总任务完成掩盖失败目标。

- `draft_saved`：已存草稿；`browser_local` 必须说明仅在执行浏览器本地。
- `submitted`：已提交；只有证据明确显示审核中才称审核中，不当作已发布。
- `published`：平台证据确认已发布，附返回的作品链接。
- `needs_attention`：需人工处理；`stay` 的 `AWAITING_PUBLISH_CONFIRMATION` 表示已填写保持，未保存或发布。
- `failed` / `outcome_unknown`：失败 / 结果未知。附 `reason.message`、阶段、处理建议；原因不明就明确说不明。
- `prepare` 的 `READONLY_CHECKED` 只证明预检；模拟草稿只证明模拟链路。

如实说明是否发生接续、调用次数和未验证环节。创建 Skill、单元测试、任务入队、浏览器完成动作、平台公开发表是不同证据，不能互相替代。
